Chat-file default for Gleaner clips

With nothing set up, Gleaner now hands every clip back as a Markdown file in the chat instead of saving it to Drive or the project folder.

The session started with a question: where do clips go when there is no external storage? That led to a request to make the chat file the default on every surface: the Chrome side panel, ChatGPT, Claude Code, and Cowork. The change is committed as adf6d45. It passes every automated check, but it is not pushed, not version-bumped, and not tested live.

Decisions

Make the chat file the default on every surface

Why

The user asked for one default everywhere, including Claude Code and Cowork.

Rejected

Chat default only for the side panel and ChatGPT, keeping Claude Code on the project folder. Claude recommended this, since Claude Code had saved to the project folder since 1.2.0. The user chose every surface.

Turn the old fallback into a named destination

Why

The behavior already existed as the fallback ("give the user the Markdown file"). Naming it "This conversation" gives one place to say how a chat clip is delivered and updated, and the fallback now points at it.

Rejected

A separate new save path beside the fallback, which would describe the same thing twice.

Don't add a "conversation" preference type yet

Why

The preferences file accepts only drive, notion, cowork, local, or artifact, and scripts/validate-skills.mjs enforces that list. Each saved destination also needs a folder path or a remote ID, and a chat has neither. The cost: a user who skips setup to keep the chat default gets the setup offer again each new session, as skipping already works today.

Rejected

Adding a conversation provider now. It means changing the contract, the validator, and the tests for a need nobody has hit yet.

Name the flag --to chat

Why

Short, and it matches how people say it ("in the chat").

Rejected

--to conversation, which is longer to type.

Send a real file when possible, else one code block

Why

A real file is easiest to keep, but not every surface can send one. A code block works everywhere. Its fence is longer than any code block inside the clip, so the clip's own code can't cut it short.

Rejected

Always a code block, which loses the download where one is possible. Writing the file into browser-research/, which puts files in the repo, the thing this change stops.

Ask where to search when no stored destination is set

Why

There is no single place to look any more, and guessing could miss clips.

Rejected

Automatically searching the old defaults (Drive and browser-research/), which adds rules and still guesses.

Leave the version bump to /release

Why

The project's CLAUDE.md says to cut versions with /release, which bumps, dates the changelog entry, validates, and commits. This change adds only an Unreleased entry.

Rejected

Editing the version in plugin.json by hand.

Learnings

  • The chat file was never the default. Git history shows Gleaner 1.0.0 (a72b8b4) already defaulted to Google Drive. Handing over the Markdown file was always the fallback for when Drive couldn't be reached. Users who mostly saw chat files probably had no Drive connector at the time.
  • zsh is not bash. ${PIPESTATUS[0]} prints nothing in zsh, where the array is lowercase and starts at 1 (${pipestatus[1]}). Rerunning the command without a pipe was the reliable way to read its exit code. A bare echo ===SK also fails in zsh, because a word starting with = is treated as a command lookup.
  • One edit covered two skills. The youtube skill runs glean's step 2 to pick its destination, so changing glean's default changed video saves too. Only the youtube argument-hint needed its own edit.
  • The glean description is almost full. It is now 1,003 of the validator's 1,024-character limit. The next destination added there needs shorter wording.

Glossary

Gleaner
This Claude plugin. It saves web pages, parts of them, and YouTube videos as summarized, tagged notes.
Clip (or glean)
One saved note: a Markdown summary with Source, Saved, Category, Type, and Tags lines at the top.
Destination
Where a clip goes: the conversation, Google Drive, Notion, a Cowork project, the Claude Code project, a local path, or a claude.ai artifact.
Surface
The place Gleaner runs: the Chrome side panel, Claude Code desktop's built-in browser, Cowork, or ChatGPT.
Chrome side panel
The Claude panel inside Google Chrome.
Cowork
The Claude desktop app's project workspace, with a folder on the user's computer.
Claude Code
Anthropic's coding tool. "This project" means the folder its session works in.
--to flag
A word added to a request (--to drive, --to chat) that sets the destination for that one save.
Preferences / shared contract
Saved defaults for destination and format, with the rules in contract.md. Other skills can use them too.
Provider
A destination type the preferences file can store: drive, notion, cowork, local, or artifact.
Fallback
What Gleaner does when a destination can't be reached. It now gives the clip in the conversation.
Duplicate check
Before saving a page, Gleaner looks for an earlier clip of the same URL and asks before saving another.
Clip index
Gleaner's search over saved clips ("what did I save about X?").
Artifact
A private web page on claude.ai, and one of Gleaner's destinations.
SKILL.md
The instruction file a skill's model reads as plain text when it runs. Here it is the product itself.
Unreleased
The changelog heading for changes not yet in a version. /release turns it into a numbered entry.
/release
The project's command that bumps the version, dates the changelog, runs the checks, and commits.
Scratchpad
A temporary folder for the session, outside the project.
Code fence
The run of backticks that opens and closes a Markdown code block. A longer outer fence keeps inner code blocks from closing it early.
Strict validators
claude plugin validate --strict, run on the marketplace and the plugin by npm run validate.
