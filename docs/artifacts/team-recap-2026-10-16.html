Saving answers as Gleaner clips

Gleaner can now keep the answers Claude gives about a page, not just the page itself.

Ask a question while reading docs, get a clarification or a list of steps, then say "save that" and the answer becomes a clip. The work is open for review as PR #5 (claude/skill-page-questions-f17a91 into main). It passes every automated check, but it is not versioned and not tested live.

What changed

Save an answer you just got

Affects
users
Now

"Save that", "save that answer", "save those steps", or "save what you just told me" saves Claude's most recent answer, or the one named, as its own clip. A bare "save that" right after an answer means the answer even if text is highlighted, and that highlight isn't added later at "done". The confirmation says so. "Explain the auth flow and save it" answers first, then saves, even if the request also says "this page" or "save them".

Reach it

Plain language in the Chrome side panel or the Claude Code desktop browser. New Save answer row in the Intents table of plugins/gleaner/skills/clip/SKILL.md.

Add an answer to a clip you're collecting

Affects
users
Now

While parts are being collected, an answer is added as the next part instead of being saved alone, and the confirmation is the "Added part" line naming it as Claude's answer. "Done" saves everything together. "Add that answer" starts or extends a collection. "Save our back-and-forth about X" adds one part per question and answer.

Reach it

New first source in "Collecting parts" in SKILL.md.

Answers are kept as given, with the question as the heading

Affects
usersclip readers
Now

An answer part is headed by the user's question and keeps the answer word for word, so numbered steps and code survive. Its source line reads "Answer about" plus the page link, or "Answer, not tied to a page". Anything not from the page is marked "(not from the page)". A clip holding a single answer skips the TL;DR.

Reach it

New "Answer parts" rule in step 3 of SKILL.md.

Answers are counted in a clip's scope and in the index

Affects
users
Now

The Scope line counts answers apart from other parts, such as 2 parts, 1 answer from 1 page, or 1 answer, no page, and the clip index marks titles the same way. Only a clip with no page behind it drops the Source line and uses the Type other. In Notion, a clip without a TL;DR starts its page body at Parts.

Reach it

Step 3 rules, the Notion steps, and "Clip index" step 3 in SKILL.md.

Answers from an earlier session are refused, not rebuilt

Affects
users
Now

If the answer is no longer in the conversation, Gleaner says it can't see it and offers to answer again, rather than recreating it from memory and saving that as the original.

Reach it

New item in "Edge cases" in SKILL.md.

Answers save without a browser

Affects
users
Now

Saving an answer doesn't need a page open, so it works in Claude Code with no browser tools. Page saves still ask for a browser or a URL.

Reach it

"No browser at all" in "Where Gleaner runs" in SKILL.md.

Decisions

Extend the clip skill instead of adding a new skill

Why

Claude already answers questions about a page without any skill; the only new behavior is saving the answer. The text is already in the conversation, so nothing new has to be extracted.

Rejected

A separate "ask" or "Q&A" skill. It would compete with clip for "save that" and duplicate all of its destination and save logic. The youtube skill earned its own file only because it needs transcript extraction.

Treat an answer as a kind of part, not a new clip format

Why

One format means the destinations, duplicate check, categories, Notion fields, and index all work unchanged. A single saved answer is a part clip with one part.

Rejected

A separate "answer clip" template, which would need its own rules in every one of those places.

A bare "save that" right after an answer saves the answer

Why

The user's decision. It matches the skill's existing "act, then say what you assumed" rule, and the confirmation offers "save the page" as the correction.

Rejected

Asking every time, which adds a round trip to the most common case.

Leave "save this" behavior alone

Why

"Save this" is the skill's core page-and-highlight intent, and changing it would affect far more requests. The confirmation now points at "save that answer" instead.

Rejected

Making "save this" also mean the answer.

Mid-collection, "save that answer" adds a part rather than saving everything

Why

Saving early would clear the collection while the user may still be adding to it; one extra "done" is the cheaper mistake.

Rejected

Mirroring Save clip, which saves all parts at once.

Keep answers as given instead of summarizing them

Why

The 2–4 bullet, 150-word part limit would wreck a numbered step list, which is one of the main things users asked to keep.

Rejected

Summarizing answers like any other part.

Mark anything not from the page

Why

Clips are used later as research notes. Mixing Claude's background knowledge in with what the source said, unlabeled, is the main way this feature could mislead.

Rejected

Saving answers unlabeled, as if they were page content.

No new Type value and no auto-save

Why

The Scope line already tells answers apart, so a new Type adds nothing to search. Clips are never overwritten, so saving every answer automatically would flood the folder.

Rejected

A "Q&A" Type, which would need a change to the Notion database's select options; auto-capturing every answer.

Leave the version bump and changelog to the release skill

Why

The project's CLAUDE.md says to cut versions with /release, and only the user can run that skill. It also commits, so it finishes this work in one step.

Rejected

Bumping plugin.json and writing the changelog entry by hand in this change, which was the original proposal.

Put the YouTube answer rules in the youtube skill

Why

The youtube skill's summary section replaces the clip skill's step 3 outright, so answer rules that lived only in the clip skill would never reach video pages. A pre-PR review caught this, and the clip skill now points to the youtube skill's rule.

Rejected

Keeping the rule only in the clip skill, the first version, chosen because the change was scoped to the clip skill.

Learnings

  • The release skill is user-only. .claude/skills/release/SKILL.md sets disable-model-invocation: true, so Claude cannot bump the version itself. The plan to bump in this change was dropped after reading it.
  • The youtube skill replaces the clip skill's step 3. A rule added only to the clip skill's step 3 silently doesn't apply on video pages; video-specific rules have to live in youtube/SKILL.md.
  • CI lints every Markdown file. .markdownlint-cli2.jsonc globs **/*.md, so new Markdown anywhere in the repo, including this recap's record, must pass markdownlint.
  • Plugin validation doesn't check frontmatter YAML. The two claude plugin validate runs pass even with broken frontmatter, so a separate Ruby YAML parse was run. The new description measured 803 characters against the 1024 limit.
  • A frontmatter title: counts as the page heading. Markdownlint's single-heading rule (MD025) flagged the recap record for having both a title: and a top-level heading, so the record carries the title only in frontmatter.
  • Main moved during the work. A skills usage guide landed on main mid-session; after syncing, it needed its own "Save an answer" section.
  • Nothing else was tried and abandoned.

Glossary

Gleaner
A Claude plugin that saves what you read as summarized, tagged clips.
Clip
One saved note: a summary with source, date, category, type, and tags.
Skill
A Markdown instruction file Claude reads at runtime; Gleaner's are clip and youtube.
clip skill
plugins/gleaner/skills/clip/SKILL.md, which holds all of Gleaner's saving behavior.
youtube skill
The video-specific skill, which reads the clip skill first and changes only what differs for video.
Intent
What a request is asking for, such as Save page, Add part, or the new Save answer.
Part
One piece of a clip being collected: a highlight, a described section, pasted text, or now an answer.
Part clip
A clip built from collected parts, each under its own heading.
Answer part
A part whose text is Claude's answer and whose heading is the user's question.
Scope
The clip header line that counts its parts, answers, and pages.
Type
The kind of source page, such as docs, article, or video.
Clip index
The table Gleaner returns when asked what was saved.
Frontmatter
The YAML block at the top of a skill file; its description decides when the skill triggers.
Four-place sync rule
The repo rule that the destination and surface list must match in four descriptions.
/release
The project command that bumps the version, writes the changelog, validates, and commits.
Markdownlint
The Markdown style checker CI runs on every .md file.
Chrome side panel
Claude's panel inside Chrome, where Gleaner reads the open tab.
Claude Code desktop browser
The built-in browser pane in the Claude Code desktop app.
Notion
A notes app; Gleaner can save each clip as a page in a Notion database.
TL;DR
The 2–3 sentence summary at the top of a clip.
PR #5
The pull request on GitHub that carries this work for review.
